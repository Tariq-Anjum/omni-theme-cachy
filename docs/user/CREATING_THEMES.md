# Creating Themes

A theme is a directory under `themes/` (or any directory you pass with
`--root`): declarative TOML plus optional artwork. Copy `themes/default/`
as a starting point — it validates cleanly and passes WCAG AA.

## Minimal layout

```
my-theme/
├── theme.toml
├── colors.toml
├── surfaces.toml      # optional but recommended
└── wallpapers/default.png   # optional
```

## 1. `theme.toml`

```toml
[theme]
name = "My Theme"
id = "my-theme"        # lowercase, no spaces; used by state + overlays
version = 1            # positive integer
mode = "dark"          # or "light"

[wallpaper]
default = "wallpapers/default.png"
```

All four `[theme]` keys are required. `mode` mirrors Plasma scheme
polarity. Unknown sections produce validation warnings.

## 2. `colors.toml`

Flat table, normalized `#RRGGBB`. Required roles (validation errors when
missing — the complete list is in
[`../architecture/THEME_MODEL.md`](../architecture/THEME_MODEL.md)):

```toml
# surfaces
background         = "#14161c"
darker_background  = "#0e1015"
dark_background    = "#101218"
lighter_background = "#1a1d25"
# text
foreground         = "#d6dae2"
bright_foreground  = "#f5f7fa"
light_foreground   = "#eef0f4"
dark_foreground    = "#8a919d"
muted              = "#7d8593"
# interaction
accent             = "#4f9eea"
accent_secondary   = "#8f6caf"
selection          = "#294664"
# status
success = "#82a55b"
warning = "#d9a05b"
error   = "#d9564f"
info    = "#5b8ec4"
# base + bright hues (red, green, yellow, blue, magenta, cyan and bright_*)
red  = "#d9564f"
green = "#82a55b"
# ...
# the ANSI ramp, color0..color15
color0 = "#0e1015"
# ...
```

44 roles total: 28 semantic + `color0`–`color15`. Extra roles are allowed
(warning) and can be referenced by templates.

## 3. `surfaces.toml` (optional)

How UI surfaces *use* the palette, at `group → key → value` granularity.
Known groups: `popups`, `controls`, plus the shell-chrome groups
`panel`, `kwin` and `tooltips` (unknown groups allowed, warned):

```toml
[popups]
background    = "#1e222b"
border        = "#4f9eea"
border-width  = 2

[controls]
normal-border = "#3a4150"
focus-border  = "rgba(4f9eeaee) rgba(8f6cafee) 45deg"
```

Value grammar: `#RRGGBB` colors; gradients as 2+ `rgba(RRGGBBAA)` stops
with optional `Ndeg` angle; border widths as int or 1–4-int list
(`"2 4"` = top/bottom, left/right); `<key>-alpha` companions in `[0, 1]`;
bare non-negative ints for dimensions; `opacity` keywords
(`opaque` / `translucent` / `adaptive`, or int codes 0/1/2); plain
identifier strings for `theme` / `library`. Anything malformed is a load
error, reported with the group and key.

### Shell chrome groups (plasma-chrome adapter)

The `panel`, `kwin` and `tooltips` groups are applied by the
`plasma-chrome` adapter as **surgical, journalled key edits** to KDE
user state — never whole-file overwrites — with exact rollback:

```toml
[panel]
opacity = "translucent"     # appletsrc [PlasmaViews][Panel <id>][Defaults]

[kwin]
theme = "Breeze"            # kwinrc [org.kde.kdecoration2] (install the theme first)

[tooltips]
background = "#1e222b"      # kdeglobals [Colors:Tooltip] Background*
foreground = "#d6dae2"      # kdeglobals [Colors:Tooltip] Foreground*
```

`[panel] opacity` applies to every panel containment; plasmashell and
KWin are asked to reconfigure so changes land live.

## 4. Wallpaper

Declare `default` relative to the theme directory. Formats (sniffed by
magic bytes): png, jpeg, gif, bmp, webp. Ship **only artwork you have
rights to** — generated or clearly-licensed files. The default theme's
wallpaper is generated by `scripts/generate_default_wallpaper.py`
(original work, MIT-licensed); reuse that script for a procedurally
generated image.

### Generating a theme from a wallpaper

`omni theme create` extracts a full 44-role palette from any image
(deterministic pure-Python k-means; stdlib PNG decoder, Pillow used when
available for JPEG/WebP) and writes a complete theme directory:

```sh
omni theme create --from-wallpaper ~/Pictures/sunset.png --name "Sunset" --yes
omni theme create --from-wallpaper sunset.png --name "Sunset" --apply --yes --json
```

The GUI (`gui/omni-settings-gui`) drives the same pipeline with previews
and per-role editing; `gui/omni-wallpaper-daemon` re-themes automatically
whenever the desktop wallpaper changes.

## 5. Theme-tier templates (optional)

A theme may ship its own template overrides in `<theme>/templates/`,
mirroring the registry path, e.g.
`templates/kde/OmniTheme.colors.tpl` inside the theme overrides the
built-in one for that theme only. Placeholder language:
`{{ accent }}`, `{{ accent_strip }}`, `{{ accent_rgb }}`,
`{{ mix A B T }}` (T = `0.2` / `20` / `"20%"`), `{{ kde_gradient ref }}`.
Rendering is strict — unknown variables and malformed helpers fail
validation instead of silently producing empty output.

## 6. Test before applying

```bash
omni theme validate my-theme            # or full path; --strict fails on warnings
omni theme preview my-theme --json | jq .targets, .warnings, .validation
```

Contrast warnings use WCAG 2.x AA: text pairs want ≥ 4.5:1, accent/status
UI pairs ≥ 3.0:1. They are warnings, not failures — design signals.

## Distribution notes

A theme directory is plain data: TOML + images. Everything a consumer
needs is the directory. There is **no installer yet** (see
[OVERRIDES.md](OVERRIDES.md) for the user-side location), and no
provenance filtering for downloaded themes — treat theme TOML/images from
strangers like any other downloaded data (see
[`../architecture/OWNERSHIP_AND_SECURITY.md`](../architecture/OWNERSHIP_AND_SECURITY.md)).
