# KDE Plasma 6 Adapter — Design and Verified Behaviour (Session 05)

Scope: **Color Scheme + wallpaper only.** Everything below was checked
against the live target machine (CachyOS, Plasma **6.7.4**, Wayland) —
not against KDE 5 memory or blog posts.

## Design boundaries

```
Omni Theme Model (palette + surfaces)
        |
        +--> adapters/kde  (this document)
        |       +--> Color Scheme   ~/.local/share/color-schemes/OmniTheme.colors
        |       +--> Wallpaper      Omni cache -> org.kde.image plugin
        |
        +--> future: Plasma Style adapter  (~/.local/share/plasma/desktoptheme/)
        +--> future: Global Theme adapter  (~/.local/share/plasma/look-and-feel/)
```

These are *separate KDE concepts* and stay separate adapters:

| Concept | Styles | Applied by |
|---|---|---|
| Color Scheme | Qt widget/app palette (`Colors:*` INI) | `plasma-apply-colorscheme` |
| Plasma Style | Panel/widget/OSD SVG chrome | `plasma-apply-desktoptheme` |
| Global Theme | Bundle that resets several layers at once | `plasma-apply-lookandfeel` |

The engine never collapses them into one "apply KDE theme" operation.

## Ownership model

| Artifact | Owner | Rationale |
|---|---|---|
| `~/.local/share/color-schemes/OmniTheme.colors` | **Omni** (managed target via `templates/targets.toml`) | generated by us; conflict-checked, rolled back, idempotent through the core generation machinery |
| `~/.config/kdeglobals` | **KDE** | applying a scheme makes `plasma-apply-colorscheme` copy values there, hash them and notify running apps; hand-editing breaks live repaint. We only *read* it back for verification |
| Wallpaper cache `<state>/adapters/wallpaper-cache/` | **Omni** | content-hash copies; the desktop points here so themes survive source files moving |
| `<state>/adapters/kde.json` journal | **Omni** | records the pre-Omni wallpaper plus per-theme cache entries for rollback |
| User's previous wallpaper files | **user** | never deleted, never modified |

The controlled scheme id is `OmniTheme` (validated against a safe-id
regex); filename stem, `[General] ColorScheme` value and CLI lookup name
are identical so `plasma-apply-colorscheme OmniTheme` is unambiguous.

## Color Scheme generation

* The palette→KDE mapping lives in `adapters/kde/colors.py`
  (`KDE_COLOR_MAP`, `POPUPS_MAP`, `SURFACE_UNSUPPORTED`) and is locked
  to the shipped templates by unit tests.
* Section/key vocabulary mirrors real Plasma 6 files (`BreezeDark`,
  verified on this machine): sets `Window/View/Button/Selection/
  Tooltip/Complementary/Header`; per-set keys `BackgroundNormal/
  BackgroundAlternate/DecorationFocus/DecorationHover/Foreground{
  Normal,Inactive,Active,Link,Negative,Neutral,Positive,Visited}`;
  effect blocks `ColorEffects:{Disabled,Inactive}` copied verbatim from
  upstream (they are effect parameters, not theme colors); plus
  `[General]`, `[KDE] contrast=4`, `[WM]`.
* Semantic highlights: `accent` → Decoration*/ForegroundActive;
  `selection` → Selection fill with `bright_foreground` text;
  success/warning/error/info → Positive/Neutral/Negative/Link;
  `muted` → ForegroundInactive.
* Surface roles: `popups.background` → Tooltip/Complementary fills when
  authored; derived (background lifted toward foreground) otherwise.
  `controls.focus-border` is flattened semantically to solid accent on
  focus/hover decorations. `controls.normal-border` is reported
  **unsupported** ("no control-border keys in a color scheme") — no key
  is invented to fake coverage.

Two template tiers exercise the standard resolution order:

1. `templates/kde/OmniTheme.colors.tpl` — palette-only fallback (themes
   without `surfaces.toml` still render);
2. `themes/default/templates/kde/OmniTheme.colors.tpl` — theme-tier
   override mapping the authored popup elevation.

## Wallpaper pipeline

```
theme [wallpaper] default
  → validate (magic bytes: png/jpeg/gif/bmp/webp)
  → copy into <state>/adapters/wallpaper-cache/<theme>-<sha256[:12]>.<ext>
  → apply via plasma-apply-wallpaperimage (native tool; no guessed DBus fallback)
  → verify by reading the ACTIVE wallpaper back from plasmashell
```

Read-back uses `qdbus6 … evaluateScript` walking `desktops()` with
`currentConfigGroup = ["Wallpaper","org.kde.image","General"]` and falls
back to scanning `plasma-org.kde.plasma.desktop-appletsrc`. There is no
DBus apply path: qdbus6 cannot reliably marshal `setWallpaper`'s
QVariantMap, so when the native tool is missing the adapter reports
that instead of guessing.

Rollback restores, in order of preference: the restored generation's
own theme wallpaper (journal history), the most recent entry (anonymous
context), or the recorded pre-Omni original. Non-image selections
(e.g. slideshow folders) are reported and left untouched.

## Verified native-command matrix

| Command | Binary (verified) | Plasma tested | Success criteria | Failure behaviour |
|---|---|---|---|---|
| `plasma-apply-colorscheme OmniTheme` | `/usr/bin/plasma-apply-colorscheme` | 6.7.4 | exit 0; `kdeglobals [General] ColorScheme == OmniTheme`; running apps repaint | non-zero exit captured into adapter errors; activation DEGRADED (adapter non-critical) |
| `kreadconfig6 --file kdeglobals --group General --key ColorScheme` | `/usr/bin/kreadconfig6` | 6.7.4 | stdout equals expected id | mismatch ⇒ verify error naming actual value |
| `plasma-apply-wallpaperimage <cached.png>` | `/usr/bin/plasma-apply-wallpaperimage` | 6.7.4 | exit 0; read-back shows `file://<cached>` on every screen | non-zero exit ⇒ adapter error; journal untouched |
| `qdbus6 org.kde.plasmashell /PlasmaShell evaluateScript <script>` | `/usr/bin/qdbus6` | 6.7.4 | lines `screen\|url`; url equals cached image URI | empty/unavailable ⇒ appletsrc scan fallback; if that fails too ⇒ verify error |

Live end-to-end run performed on the target machine (2026-08-25):

```
omni theme preview default --json     → DRY_RUN, kde supported (6.7.4)
omni theme apply  default --yes       → VERIFIED; kdeglobals=OmniTheme;
                                        wallpaper = Omni cache copy
omni status --json / omni theme current → consistent / "default"
omni theme apply default-alt --yes    → VERIFIED (orange accent live)
omni theme rollback --yes             → ROLLED_BACK; accent blue again,
                                        wallpaper = default's cache entry
```

## Tests

* `tests/unit/test_kde_colors.py` — mapping tables, model, serializer,
  template parity (both tiers), registry declaration.
* `tests/unit/test_kde_detection.py` — hermetic environment probes.
* `tests/unit/test_kde_wallpaper.py` — sniffing, caching, journal
  (incl. v1→v2 migration), backend apply/read-back with fake runners.
* `tests/unit/test_kde_phases.py` — capability/plan/render/apply/
  verify/rollback with injected env+runners; never touches real `$HOME`
  (`fake_home` fixture).
* `tests/integration/test_kde_adapter.py` — `pytest.mark.kde`; skips
  cleanly off Plasma. Read-only against the live session (dry-run,
  staging into tmp state root, wallpaper read-back). Destructive
  verification is done manually via the CLI, as recorded above.

Run everything without KDE: `pytest -m "not kde"`.
